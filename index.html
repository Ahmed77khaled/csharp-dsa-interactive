Console Output, Comments & Variables

▼

🖥️ Output to screen

  • Console.Write(); → عرض المخرجات على الشاشة بدون سطر جديد.
  • Console.WriteLine(); → عرض المخرجات والنزول لسطر جديد.

💬 Comments (التعليقات)

  • // تعليق سطر واحد
  • /* تعليق متعدد الأسطر */

📦 Variables (المتغيرات)

int x;               // declaration (إعلان)
x = 123;             // initialization (تعيين قيمة)
int x = 123;         // declaration + initialization

Console.WriteLine(x);                         // 123
Console.WriteLine("this is my number: " + x); // this is my number: 123

تعريف أكثر من متغير من نفس النوع: int x = 5, y = 6, z = 50;

قواعد تسمية المتغيرات (Naming Rules):
  1. تحتوي على حروف وأرقام والشرطة السفلية _.
  2. تبدأ بحرف أو بشرطة سفلية _.
  3. يُفضل أن تبدأ بحرف صغير، ولا تحتوي على مسافات إطلاقاً.
  4. حساسة لحالة الأحرف (Case Sensitive) → myVar ≠ myvar.
  5. حظر استخدام الكلمات المحجوزة في C# مثل int.
  6. يجب أن تكون الأسماء فريدة ومُعبرة ووصفية.
✏️ تمرين تطبيقي: قم بتعريف متغيرين num1 و num2، واطبع ناتج ضربهما في رسالة توضيحية.

Type Casting & Conversion

▼

🔄 التحويل بين الأنواع (Type Casting)

هو إسناد قيمة من نوع بيانات إلى نوع آخر. ينقسم في C# إلى نوعين رئيسيين:

1. Implicit Casting (تلقائي)

التحويل التلقائي من نوع أصغر حجماً إلى نوع أكبر دون فقد في البيانات:

char → int → long → float → double

int myInt = 9;
double myDouble = myInt; // يتم التحويل تلقائياً int → double

2. Explicit Casting (يدوي)

التحويل اليدوي من نوع أكبر إلى نوع أصغر عن طريق كتابة النوع بين قوسين (type):

double → float → long → int → char

double myDouble = 9.78;
int myInt = (int)myDouble; // double → int يدوي
Console.Write(myInt);      // 9 (يتم قطع الكسر العشري وليس تقريبه)
⚠️ تنبيه: الـ Explicit Casting يقوم بحذف الجزء العشري (Truncate) تماماً، فالقيمة 9.78 تصبح 9 وليست 10.

3. دوال الفئة Convert

طريقة مدمجة وشاملة للتحويلات الصريحة بين الأنواع المختلفة:

  • Convert.ToBoolean()
  • Convert.ToDouble()
  • Convert.ToString()
  • Convert.ToInt32() (تحويل إلى int)
  • Convert.ToInt64() (تحويل إلى long)

Comparison, Logical Operators & Strings

▼

⚖️ Comparison Operators (معاملات المقارنة)

ترجع دائماً قيمة منطقية (bool): == متساوي، != لا يساوي، > أكبر، < أصغر، >=، <=.

🔀 Logical Operators (المعاملات المنطقية)

  • && (AND) → صحيح فقط إذا تحقق كلا الشرطين.
  • || (OR) → صحيح إذا تحقق أحد الشرطين على الأقل.
  • ! (NOT) → يعكس النتيجة المنطقية.

📜 Strings (السلاسل النصية)

خاصية الطول:

string name = "Mohamed";
Console.WriteLine(name.Length); // 7

دمج النصوص (Concatenation) — 3 طرق:

string firstname = "John ";
string lastname = "Doe";

// 1. باستخدام معامل +
Console.WriteLine(firstname + lastname);              // John Doe

// 2. دالة string.Concat (تأخذ فاصلة بين المتغيرات وليس علامة +)
Console.WriteLine(string.Concat(firstname, lastname)); // John Doe

// 3. String Interpolation باستخدام علامة $
Console.WriteLine($"{firstname} {lastname}");          // John Doe

Else If, Ternary & Switch

▼

1. If / Else If / Else

if (score >= 90) {
    Console.WriteLine("A");
} else if (score >= 75) {
    Console.WriteLine("B");
} else {
    Console.WriteLine("C");
}

2. Ternary Operator (المعامل الشرطي المختصر)

variable = (condition) ? true_expression : false_expression;

int age = 20;
string result = (age >= 18) ? "Adult" : "Minor"; // Adult

3. Switch Statement

switch (day) {
    case 1:
        Console.WriteLine("Monday");
        break;
    case 3:
        Console.WriteLine("Wednesday");
        break;
    default:
        Console.WriteLine("Other Day");
        break;
}

ملاحظات هامة: الكلمة break تخرج من كتلة الـ switch، والكلمة default تُنفذ عند عدم تطابق أي حالة.

While, Do-While & For Loops

▼

1. While Loop (الفحص أولاً ثم التنفيذ)

int i = 0;
while (i < 5) {
    Console.WriteLine(i);
    i++; // ⚠️ إلزامي لتفادي الـ Infinite Loop
}

2. Do-While Loop (التنفيذ أولاً ثم الفحص)

يضمن تنفيذ الكود مرة واحدة على الأقل حتى لو كان الشرط غير محقق من البداية:

int i = 0;
do {
    Console.WriteLine(i);
    i++;
} while (i < 5);

3. For Loop (تكرار معلوم المدى)

for (statement1; statement2; statement3) { ... }

العبارةتوقيت التنفيذالدور الهندسي
Statement 1مرة واحدة قبل بدء الدورانتهيئة العداد int i = 0
Statement 2قبل كل دورةفحص شرط الاستمرار i < 5
Statement 3بعد كل دورةتحديث العداد i++

Nested Loops & Foreach

▼

🔁 Nested Loops (الدورانات المتداخلة)

for (int i = 0; i < 3; i++) {
    Console.WriteLine("Outer: " + i);
    for (int j = 0; j < 3; j++) {
        Console.WriteLine("  Inner: " + j);
    }
}

ينتج عنها 3 دورات داخلية لكل دورة خارجية، بإجمالي 9 تكرارات (نموذج التعقيد O(n²)).

🔄 Foreach Loop (الدوران المخصص للمجموعات)

مخصص للقراءة المباشرة من المصفوفات والمجموعات بدون الحاجة لإدارة عداد Index يدوي:

string[] cars = { "Volvo", "BMW", "Ford" };
foreach (string car in cars) {
    Console.WriteLine(car);
}

📐 2D Rectangular Arrays (المصفوفات ثنائية الأبعاد)

شبكة مستطيلة ثابتة الأبعاد، تُعرّف بفاصلة داخل الأقواس int[,]:

int[,] numbers = { { 1, 4, 2 }, { 3, 6, 8 } };
Col 0Col 1Col 2
Row 0142

الوصول: numbers[0, 2]; // 2

الدوران المتداخل السليم:

for (int i = 0; i < numbers.GetLength(0); i++) {      // عدد الصفوف

مصفوفة عناصرها عبارة عن مصفوفات، وكل صف يمكن أن يكون له طول مختلف تماماً:

int[][] jagged = new int[3][];
jagged[0] = new int[] { 1, 2 };          // عنصرين
jagged[1] = new int[] { 3, 4, 5, 6 };    // 4 عناصر
jagged[2] = new int[] { 7 };             // عنصر واحد

Console.WriteLine(jagged[1][3]); // 6

Methods, Parameters & Overloading

▼

⚙️ Methods (الدوال)

كتلة برمجية مستقلة لا تعمل إلا عند استدعائها صراحة:

class Program {
    static void myMethod() { // إنشاء الدالة
        Console.WriteLine("Hi!");
    }
    static void Main(string[] args) {
        myMethod(); // استدعاء الدالة
    }
}
  • void → لا تُرجع أي قيمة.
  • static → تتبع الكلاس مباشرة ولا تتطلب إنشاء كائن (Object).

Parameters vs Arguments: المتغير في توقيع الدالة يُسمى Parameter، بينما القيمة المُرسلة أثناء الاستدعاء تُسمى Argument.

🎯 Method Overloading (التحميل الزائد للدوال)

تعريف دوال تحمل نفس الاسم تماماً ولكن بـ توقيع مختلف (Different Parameters):

static int Add(int a, int b) { return a + b; }
static double Add(double a, double b) { return a + b; }
static int Add(int a, int b, int c) { return a + b + c; }
⚠️ قاعدة هامة في الـ Interviews: تغيير نوع الإرجاع (Return Type) وحده لا يعتبر Overloading صالحاً ويسبب Compile Error:
static int Calc(int x) { ... }
// static double Calc(int x) { ... } ❌ خطأ تركيبي

Default Parameters & Return Values

▼

🌍 Default Parameters (المعاملات الافتراضية)

إذا تم استدعاء الدالة بدون تمرير الـ Argument، تستخدم القيمة الافتراضية المحددة لها:

static void myMethod(string country = "Norway") {
    Console.WriteLine(country);
}

myMethod("India"); // India
myMethod();        // Norway (القيمة الافتراضية)
⚠️ قاعدة الترتيب الإلزامية: المعاملات الافتراضية يجب أن تُكتب بعد المعاملات العادية وليس قبلها:
✅ static void x(string name, string country = "Egypt")
❌ static void x(string country = "Egypt", string name) // خطأ فادح

🔙 Return Values (القيم المرجعة)

يتم استبدال الكلمة void بنوع البيانات المُراد إرجاعه واستخدام الكلمة المفتاحية return:

static int myMethod(int x) {
    return 5 + x;
}
Console.WriteLine(myMethod(3)); // 8

ref & out Parameters

▼

تُتيح كلتا الكلمتين تمرير المتغير بالمرجع (By Reference) للتأثير في المتغير الأصلي أو إرجاع قيم إضافية:

1. ref (التمرير بالمرجع لتعديل المتغير الأصلي)

يجب تهيئة المتغير بقيمة أولية قبل استدعاء الدالة:

static void AddTen(ref int x) {
    x += 10;
}
int number = 5;
AddTen(ref number);
Console.WriteLine(number); // 15 (تغيرت القيمة الأصلية)

2. out (إلزام الدالة بتعيين قيمة)

لا تشترط تهيئة المتغير قبل الاستدعاء، ولكن الدالة مُلزمة إجبارياً بتعيين قيمة له قبل الخروج. الاستخدام النموذجي الواقعي هو الدالة int.TryParse:

string input = "123";
if (int.TryParse(input, out int value)) {
    Console.WriteLine("Parsed: " + value); // 123
} else {
    Console.WriteLine("Invalid integer");
}

جدول المقارنة الحاسم:

القاعدةrefout
هل يلزم إعطاؤه قيمة قبل الاستدعاء؟✅ نعم إجباري❌ لا يشترط
هل الدالة مجبرة على إسناد قيمة له؟❌ لا يشترط✅ نعم إجباري على كل مسارات الإرجاع
هل يمكن للدالة قراءة قيمته السابقة؟✅ نعم❌ لا يمكن القراءة إلا بعد الإسناد
الاستخدام الهندسي النموذجيتعديل متغير موجود مسبقاًإرجاع أكثر من قيمة من دالة واحدة

List<T> — Dynamic Collection

▼

على عكس المصفوفات العادية ذات الحجم الثابت، تتميز List<T> بكونها ديناميكية الحجم (تتمدد وتنكمش تلقائياً) مع إضافة وحذف العناصر:

using System.Collections.Generic;

List nums = new List();
nums.Add(10);           // إضافة عنصر للنهاية
nums.Add(20);
nums.Add(30);

Console.WriteLine(nums[0]);           // 10 (الوصول بالفهرس)
Console.WriteLine(nums.Count);        // 3 (خاصية العدد وليس .Length)

nums.Remove(20);                      // حذف أول عنصر مطابق بالقيمة
nums.RemoveAt(0);                     // حذف العنصر بالمؤشر 0
Console.WriteLine(nums.Contains(30)); // True
nums.Sort();                          // ترتيب تصاعدي
nums.Clear();                         // حذف كافة العناصر

أهم دوال وخصائص List<T>:

Big-O: Time & Space Complexity

▼

يصف رمز Big-O معدل نمو استهلاك الخوارزمية للموارد (الوقت والذاكرة) مع زيادة حجم المدخلات n. هو يصف معدل النمو وليس عدد الثواني.

جدول درجات التعقيد الزمني الشائعة:

الرمزالاسم الهندسيمثال عملي شهير
O(1)Constant (ثابت)الوصول لعنصر مصفوفة بالفهرس arr[0]
O(log n)Logarithmic (لوغاريتمي)البحث الثنائي (Binary Search) في مصفوفة مرتبة
O(n)Linear (خطي)دوران واحد للمرور على كافة عناصر المصفوفة
O(n log n)Log-Linearخوارزميات الترتيب الفعالة مثل Merge Sort و Array.Sort()
O(n²)Quadratic (تربيعي)دوران متداخل (Nested Loop) يدور كل منهما n مرة
O(2ⁿ)Exponential (أسي)خوارزميات الـ Brute-Force التكرارية مثل فيبوناتشي التراجعي
ترتيب الأداء من الأفضل إلى الأسوأ:
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
الأفضل ◄─────────────────────────────────────────────► الأسوأ

⚡ القواعد الذهبية لحل مسائل الامتحانات (Fast Rules):

القاعدة البرمجيةالتعقيد الزمني الناتج
دوران مفرد بسيط على n عنصرO(n)
دوران متداخل (Nested) كلاهما يدور n مرةO(n²)
دورانين منفصلين يتبعان بعضهما على التواليO(n + n) = O(n) (تجاهل الجمع)
تجاهل الثوابت والمعاملات الرقميةO(3n) تُبسط إلى O(n)
الإبقاء على الحد الأعلى نمواً وحذف الأقلO(n² + n) تُبسط إلى O(n²)

تعقيد الذاكرة (Space Complexity):

  • O(1) Extra Space → استخدام عدد ثابت من المتغيرات مهما كبر حجم المدخلات.
  • O(n) Extra Space → إنشاء مصفوفة أو قائمة جديدة يتناسب حجمها مع حجم المدخلات.

Common Pitfalls & Coding Guidelines

▼

أخطاء شائعة جداً يقع فيها المبرمجون والطلاب في الامتحانات، تم تجميعها مع الحل الهندسي المعتمد الصحيح لكل منها:

1. خطأ دمج النصوص بـ string.Concat()

استخدام + داخل دالة Concat يجعلها بلا فائدة، والصحيح استخدام فاصلة بين الوسائط:

❌ Console.WriteLine(string.Concat(fname + lname));
✅ Console.WriteLine(string.Concat(fname, lname));

2. خطأ الجمع مع التعريف في سطر واحد int y += x;

لا يمكن في لغة C# الجمع التراكمي على متغير أثناء الإعلان عنه لأول مرة؛ يجب تعريفه وإسناد قيمة أولية أولاً:

❌ int x = 10; int y += x;
✅ int x = 10; int y = 5; y += x;

3. نسيان زيادة العداد في الـ While Loop

إهمال كتابة i++ داخل الـ while يؤدي فوراً إلى تجميد البرنامج في دورة لا نهائية (Infinite Loop):

❌ while(i < 5) { Console.WriteLine(i); }
✅ while(i < 5) { Console.WriteLine(i); i++; }

4. زيادة عداد الصف في الدوران الداخلي للـ 2D Array

خطأ نسخي شائع بزيادة i++ بدلاً من j++ في الدوران الداخلي للأعمدة:

❌ for(int j=0; j < arr.GetLength(1); i++)
✅ for(int j=0; j < arr.GetLength(1); j++)

5. حالة الأحرف في دوال C# (حساسية الـ Case)

استدعاء الدالة بحرف كبير من كائن نصي يسبب Compile Error لأن دوال الكائنات في C# تبدأ بأحرف صغيرة أو بحسب التوثيق الرسمي:

❌ name.IndexOf("m"); مع Name.IndexOf بحرف N كبير كاسم متغير
✅ name.IndexOf("m"); مع مطابقة دقيقة لاسم المتغير الصغير

6. الخلط بين .Length و .Count

المصفوفات تستخدم الخاصية .Length بينما القوائم List<T> تستخدم .Count:

❌ list.Length أو arr.Count
✅ arr.Length للمصفوفة و list.Count للقائمة
